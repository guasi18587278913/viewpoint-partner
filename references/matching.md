# 提取、匹配与卡片

## 得到要交出的东西

观点是来源对某个问题作出的判断、解释、价值取舍或主张。它可以温和、具体、有条件；不必反常识。纯事件、数字、概念定义和方法名不能自动当成作者观点。一个故事若只提供细节，就作为事例保存；从故事进一步归纳的判断标为本次推断。

提取的是作者实际表达的内容，不是把全文换成助手最熟悉的道理。允许保留不认同或互相冲突的观点供用户比较，不负责替用户选定价值立场。

## 一条观点必须读清楚的关系

- 他在回答什么问题，判断针对谁、哪种情境？
- 他认同这句话，还是引述后反驳？引号内是谁说的？
- 这是作者自己的评论、转述一本书、引用他人，还是作者自报的经历？
- 他给了什么理由或故事，后面有没有收回、限定、改口、列反例？
- 这是原句、忠实概括，还是当前助手跨领域迁移后的新判断？

对史实、研究、商业数据保留原文日期和来源层级；当前任务如果只引用作者观点，写“某某在文章中认为”。若要把数据当今天的现状或把研究当已确立事实，需要另做相应核验。不要自动展开外部事实调查，也不要默默把旧材料写成现在。

## 适配检查

先把当前文本的问题和来源的问题各写成一句话。对照的应当是**问题、作用关系、前提与评价标准**，不是相同名词。

三种可用关系：

- 直接回应：双方在讨论同一个问题，来源有明确看法。
- 补充或不同解释：为同一个现象补充变量、条件或可能原因；证据未到时仍是候选解释。
- 跨领域借用：能指出双方对应的角色、关系、代价或机制，并说明差别；它是类比或启发，不自动证明当前事情的因果。

反对关系需额外检查：双方是否对同一对象、同一条件、同一问题提出互不兼容的判断。补条件不等于反对，两句话能同时成立时不要标“打脸”。

示例：

- “小众产品没人购买”可以借“少数人强烈喜欢”和“所有人都无感”的区别提出判断标准，但仅有销量低，仍不能断言该产品平庸。
- “工具使用更快却留不住用户”可以借替换成本提出解释；没有迁移、学习或协作成本的实际材料，不说已经证明原因，更不编同事怕学不会。
- “悲观的起因”不直接回答“悲观判断是否准确”。“个性化供需可以撮合”与“可替代歌曲的注意力集中”可以同时成立，不是一对反方观点。

这些是校准例子，不是固定选题或只准用的机制。

## 可以积累的观点卡

日常回答不必展示 JSON。确需保存时使用下面字段，使观点、原句和当前应用分开。查看 `seed-viewpoints.json` 的一个相关样本即可，不默认读全部样本。

```json
{
  "id": "简短稳定标识",
  "question": "这条观点实际回答的问题",
  "claim": "忠实概括，不冒充原话",
  "claim_kind": "explanation / evaluation / advice / distinction",
  "source": {
    "article_id": "a-...",
    "article_title": "正文核对后的标题",
    "article_author": "讲述/撰写这篇文章的人或null",
    "attribution": "author_view / retelling / quoted_person / unclear",
    "original_claimant": "若是转述，记录原持有者；未知则null",
    "attribution_note": "谁讲谁，原文哪些话支持这一归属",
    "article_version": "read返回的版本",
    "text_sha256": "read返回的SHA-256"
  },
  "quote": "足够表达判断、逐字可核的原话",
  "reasoning_summary": "保留原文从什么到什么的论述过程",
  "reasoning_excerpt": "支持上项概括的连续原文片段",
  "cases": [{
    "kind": "reported_case / author_experience / study_report / teaching_hypothesis / metaphor",
    "summary": "人物、动作、结果及与观点的关系；不要只剩故事名字",
    "excerpt": "连续原文片段"
  }],
  "conditions": ["原文限制、尚未核验的部分"],
  "search_phrases": ["原词", "其他表达", "可能面对的问题"],
  "usable_for": ["可以考虑的文本情境；这是本Skill的应用判断"],
  "not_enough_for": ["不能据此推定的事情"]
}
```

卡片是通往全文的入口。保留文章 ID、版本与足够上下文，不靠卡片抹平作者差异。一个案例在多篇转述中出现，只算同一案例；同一主张换措辞不算多个候选。

## 面向用户怎么写

让用户能比较“我是否愿意在这篇文章中说这句话”。直接给看法与内容，别只列“边界感、稀缺、替换成本”几个词。写明原话/概括，具体说明原文中的事，再指出对应用户哪一处。

例如可以说：“更适合你这段的是……。某某在《文章》中谈……时提出……，他用……说明。放在你写到……之后，可以接成……。不过你现在还没有……，所以这里先作为一个待验证解释。”不用每条都写满所有标签，读者应看到内容而非台账。

只要原话时省略接法；只要观点素材时不交整篇稿。用户要求完整合并稿才合并，新增事实保持第三方归属，锁定内容保留。
